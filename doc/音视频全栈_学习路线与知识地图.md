# RK3588 音视频全栈 · 学习路线与知识地图

> **目标**：成为音视频开发全栈人才，覆盖 **编解码 → 转码 → 转存（NVR）→ 流媒体服务 → 客户端播放** 整条链路
> **平台**：正点原子 ATK-DLRK3588 + Linux 5.10 Buildroot
> **开始日期**：2026-09-29
> **我的优势**：Android 开发经验，正好覆盖"客户端播放"这一端（MediaCodec、ExoPlayer、WebRTC）

---

## 一、为什么用 RK3588 学

| 能力 | RK3588 | 对应的方向 |
|---|---|---|
| 硬件解码 | H.265/VP9 **8K@60**，H.264 8K@30，AV1 4K@60，**分辨率低时可以多路并行** | NVR 多路解码、转码 |
| 硬件编码 | H.264/H.265 **8K@30**，可以多路并行 | 转码、推流 |
| JPEG 编解码 | 编码每秒 9000 万像素，解码 1080p@280fps | 抓拍、缩略图 |
| RGA | 2D 缩放、格式转换、旋转、叠加 | 转码缩放、OSD 水印、多画面拼接 |
| NPU | 6 TOPS | 智能分析（进阶） |

**ATK-DLRK3588 开发板的接口**（来自《开发板规格书 V1.4》）：

| 接口 | 用途 |
|---|---|
| **2 路千兆以太网** | 一路接 IPC 摄像头网络，一路接外网（NVR 常见的双网口布局） |
| **SATA 硬盘接口** | 存录像 |
| **4 个 MIPI CSI 摄像头接口** | 本地摄像头采集（官方适配的是 IMX415） |
| **1 路 HDMI 输入** | 采集外部视频源，适合做采集卡、转码器 |
| 2 路 HDMI 输出 + 2 路 MIPI DSI | 本地预览、多画面显示 |
| ES8388 音频 + 麦克风 | 音频采集和播放 |
| 5G 接口、Wi-Fi/蓝牙 | 无线回传 |

> 规格书"应用领域"里明确写了：**NVR 存储、流媒体直播、网络摄像头**。

## 二、全链路总览

```
 ┌─────────┐   ┌──────────────┐   ┌──────────┐   ┌────────────┐   ┌──────────┐   ┌──────────┐
 │  采集    │──►│  编码 / 转码   │──►│   传输    │──►│  流媒体服务  │──►│  存储     │──►│  播放     │
 └─────────┘   └──────────────┘   └──────────┘   └────────────┘   └──────────┘   └──────────┘
  MIPI 摄像头     MPP 硬件编解码      RTSP/RTP       协议转换          NVR 录像        Android App
  HDMI 输入       RGA 缩放/叠加       RTMP           分发/转发         MP4/TS 分段     Web 播放器
  IPC 拉流        ALSA + AAC          HLS/WebRTC     GB28181/ONVIF     检索/回放       VLC/ffplay
  麦克风          音视频同步          SRT            鉴权/多路并发     循环覆盖
```

### 阶段 1：编解码基础 · 项目 `yuv2h264` / `h264toyuv`
**目标**：自己写出硬件编码器和解码器。

| 内容 | 说明 |
|---|---|
| 功能 | ① 读 YUV 文件 → MPP 编码 → 写出 `.h264`/`.h265` 文件 ② 读 `.h264` 文件 → MPP 解码 → 写出 YUV 文件 |
| 学到什么 | MppCtx/MppFrame/MppPacket/MppBuffer、MppEncCfg 参数设置、info change、stride 对齐、码率控制（CBR/VBR/AVBR）、GOP、SPS/PPS |
| 验收标准 | Mac 上用 VLC 能播放编出来的码流；用 ffprobe 检查 GOP 和码率符合设置；在板子上用 `top` 看 CPU 占用很低 |
| 资料 | `MPP开发指南_学习笔记.md`、SDK 里的 `external/mpp/test/mpi_enc_test.c`、`mpi_dec_test.c` |

---

### 阶段 2：采集 + 实时推流 · 项目 `cam_rtsp`
**目标**：用摄像头做一个"网络摄像头（IPC）"。

| 内容 | 说明 |
|---|---|
| 功能 | IMX415（或 USB 摄像头）采集 → MPP 编码 H.264/H.265 → RTSP 服务端，Mac 上用 VLC 拉流观看 |
| 学到什么 | V4L2 采集（mmap / **DMA-BUF 零拷贝**）、ISP 链路（mainpath/selfpath）、rkaiq、RTSP 信令、RTP 打包（H.264 用 FU-A 分片）、每个 IDR 前带 SPS/PPS |
| 进阶 | 双码流（主码流 4K + 子码流 720p，子码流用 RGA 缩放得到）、OSD 时间水印（RGA 叠加）、麦克风音频（ALSA → AAC）、音视频同步 |
| 验收标准 | VLC 拉流延迟 < 500ms；连续运行 1 小时不卡顿、内存不上涨 |
| 资料 | Camera 应用开发手册（辅助 15）、`docs/cn/Common/ISP/ISP30/Rockchip_Driver_Guide_VI_CN_v1.1.3.pdf`、RGA 开发指南、live555 或 gst-rtsp-server（工具链的 sysroot 里都有） |

---

### 阶段 3：转码 · 项目 `transcoder`
**目标**：实现"输入一路流，转成另一种格式或分辨率再输出"。

| 内容 | 说明 |
|---|---|
| 功能 | 拉 RTSP 流 → MPP 解码 → RGA 缩放 → MPP 编码 → 推 RTSP/RTMP 流，比如 **4K H.265 转成 720p H.264**，同时输出多档码率 |
| 学到什么 | 解码 → 处理 → 编码流水线、多线程和队列、DMA-BUF 在解码器、RGA、编码器之间传递（零拷贝）、帧率转换、码率自适应 |
| 进阶 | 多路并发转码，测出 RK3588 的**极限路数**；和 FFmpeg 软件转码对比 CPU 占用和延迟 |
| 验收标准 | 输出码流能正常播放；多路同时转码时帧率稳定 |
| 资料 | MPP、RGA 开发指南，`docs/cn/RK3588/Benchmark/Rockchip_RK3588_Linux_Performance_Test_Report_CN.pdf` |

---

### 阶段 4：单路录像 · 项目 `recorder`
**目标**：把网络摄像头的流存到硬盘上。

| 内容 | 说明 |
|---|---|
| 功能 | 拉 IPC 的 RTSP 流 → **不解码，直接转封装** → 按时间分段存成 MP4 或 TS 文件（比如每 10 分钟一个文件） |
| 学到什么 | FFmpeg libavformat 解封装和封装、**MP4 的 box 结构**、TS 格式、Annex-B 和 AVCC 互转、PTS/DTS 时间戳、分段时要从 I 帧切、写文件的性能 |
| 进阶 | 断电保护（MP4 的 moov 放在文件头部 / fragmented MP4）、断线自动重连、录像期间的抓拍（JPEG 编码） |
| 验收标准 | 录下来的文件能正常播放、拖动进度条；断网恢复后能自动继续录 |
| 资料 | FFmpeg 官方文档和示例（`doc/examples/remux.c`）、ISO/IEC 14496-12（MP4 格式规范） |

---

### 阶段 5：多路 NVR · 项目 `mini_nvr`
**目标**：做一个能管理多路摄像头的 NVR。

| 内容 | 说明 |
|---|---|
| 功能 | 接入 8～16 路 IPC → 同时录像 → 按时间检索 → 回放（支持倍速和拖动）→ 本地多画面预览（HDMI 输出） |
| 学到什么 | **ONVIF**（设备发现、获取流地址、云台控制）、多路并发的架构设计、**硬盘管理**（SATA 硬盘、空间满了循环覆盖最早的录像）、录像索引（SQLite）、多画面解码拼接（RGA）、DRM 显示 |
| 进阶 | 移动侦测、事件录像、报警联动 |
| 验收标准 | 16 路同时录像 24 小时稳定运行；能按时间准确找到录像并回放 |
| 资料 | ONVIF 官方规范、DRM 显示相关文档（`docs/cn/Common/DISPLAY/`） |

---

### 阶段 6：流媒体服务 · 项目 `media_server`
**目标**：让 NVR 能对外提供多种协议的服务。

| 内容 | 说明 |
|---|---|
| 功能 | NVR 对外输出 **RTSP / RTMP / HLS / HTTP-FLV / WebRTC**，支持多客户端同时观看，录像可以远程回放 |
| 学到什么 | 流媒体服务器架构（读 **ZLMediaKit** 或 **SRS** 的源码）、协议转换、GOP 缓存（新客户端秒开）、高并发网络编程（epoll）、鉴权、低延迟优化 |
| 进阶 | **GB28181**（国标，安防行业必备，接入各地平台时要用）、SRT 协议、级联转发 |
| 验收标准 | 浏览器能用 HLS/WebRTC 观看；10 个客户端同时观看不卡顿 |
| 资料 | ZLMediaKit、SRS 的源码和文档，RFC 文档（见第五节） |

---

### 阶段 7：客户端 · 项目 `nvr_app`（发挥 Android 的优势）
**目标**：写一个手机 App，远程查看实时画面和录像。

| 内容 | 说明 |
|---|---|
| 功能 | Android App：设备列表 → 多画面实时预览 → 录像时间轴 → 回放和下载 → 抓拍 |
| 学到什么 | 播放器内核（ExoPlayer / 基于 MediaCodec 自己写）、**低延迟播放**（缓冲区策略、追帧）、WebRTC Android、多路解码的性能优化 |
| 进阶 | 对讲（手机麦克风 → NVR 喇叭）、云台控制、推送报警通知 |
| 验收标准 | 局域网内打开实时画面 < 1 秒；延迟 < 500ms |

## 四、知识地图

> 边做项目边补，学会一项勾一项。⭐ 表示核心必学。

### 4.1 音视频基础理论
- [ ] ⭐ 色彩空间：RGB / YUV，采样方式 4:2:0 / 4:2:2 / 4:4:4
- [ ] ⭐ YUV 内存排布：NV12、NV21、I420、YUYV；**stride** 和对齐
- [ ] ⭐ 视频编码原理：帧内预测、帧间预测、变换、量化、熵编码
- [ ] ⭐ 帧类型：I / P / B 帧、IDR 帧、GOP、参考帧
- [ ] ⭐ H.264 码流结构：NAL 单元、SPS / PPS、Slice、Annex-B（起始码）和 AVCC（长度前缀）
- [ ] H.265 的新概念：VPS、CTU，和 H.264 的区别
- [ ] ⭐ 码率控制：CBR / VBR / AVBR / CQP，QP 和画质的关系
- [ ] 画质评估：PSNR、SSIM、VMAF
- [ ] ⭐ 音频基础：PCM、采样率、位深、声道；AAC / Opus / G.711
- [ ] ⭐ 时间戳：PTS / DTS / time_base、**音视频同步**

### 4.2 RK3588 平台
- [ ] ⭐ **MPP**：编码和解码流程、MppEncCfg、info change、三种内存模式
- [ ] ⭐ **RGA**：im2d API、缩放、格式转换、叠加
- [ ] ⭐ **V4L2**：设备节点、格式协商、mmap / DMA-BUF、`v4l2-ctl`、`media-ctl`
- [ ] ISP / rkaiq：采集链路（sensor → CSI → ISP → mainpath/selfpath）、IQ 参数文件
- [ ] ⭐ **DMA-BUF 零拷贝**：摄像头 → RGA → MPP → 显示，全程只传 fd
- [ ] DRM / KMS 显示：plane、多画面叠加
- [ ] ALSA：`libasound` 编程、ES8388 声卡配置（驱动开发指南第 12 章）
- [ ] 性能分析：CPU、DDR 带宽、VPU 负载

### 4.3 封装格式
- [ ] ⭐ **MP4**：box 结构（ftyp / moov / mdat / trak / stbl）、moov 放在文件头还是尾、fragmented MP4
- [ ] ⭐ **MPEG-TS**：PAT / PMT / PES、188 字节的包
- [ ] FLV：tag 结构（RTMP 和 HTTP-FLV 要用）
- [ ] MKV（了解即可）
- [ ] ⭐ 转封装（不解码，只换容器）

### 4.4 传输协议
- [ ] ⭐ **RTSP**：OPTIONS / DESCRIBE / SETUP / PLAY 这套信令、SDP
- [ ] ⭐ **RTP / RTCP**：包头、时间戳、H.264 打包方式（Single NAL / FU-A）、RTP over TCP 和 UDP
- [ ] ⭐ **RTMP**：握手、chunk、推流和拉流
- [ ] HLS：m3u8 播放列表、TS/fMP4 分片、延迟来源
- [ ] HTTP-FLV
- [ ] ⭐ **WebRTC**：SDP 协商、ICE / STUN / TURN、DTLS-SRTP、低延迟
- [ ] SRT：低延迟、抗丢包
- [ ] 网络基础：TCP/UDP、丢包和抖动、Jitter Buffer、带宽估计

### 4.5 工具和库
- [ ] ⭐ **FFmpeg 命令行**：转码、转封装、推流拉流、ffprobe 分析
- [ ] ⭐ **FFmpeg API**：libavformat（封装和解封装）、libavcodec、AVPacket/AVFrame
- [ ] GStreamer：pipeline、element、RK 的 mpp 插件
- [ ] live555：RTSP 服务端和客户端
- [ ] ⭐ 排查工具：**Wireshark** 抓 RTP/RTSP 包、Elecard / StreamEye 码流分析工具、VLC、ffplay

### 4.6 流媒体服务端
- [ ] ⭐ 服务器架构：接入 → 协议解析 → 媒体数据缓冲 → 分发
- [ ] ⭐ 读一个开源服务器的源码：**ZLMediaKit**（C++，功能全面）或 **SRS**（C++，文档多）
- [ ] GOP 缓存与秒开
- [ ] 高并发：epoll、线程模型、零拷贝发送
- [ ] 鉴权、HTTP API、状态统计
- [ ] 集群、级联、CDN（了解即可）

### 4.7 安防行业协议
- [ ] ⭐ **ONVIF**：WS-Discovery 设备发现、Media Profile、获取 RTSP 地址、PTZ 云台控制
- [ ] ⭐ **GB28181**：SIP 信令、设备注册、实时播放、录像回放、PS 流格式
- [ ] 海康、大华的私有 SDK（了解即可）

### 4.8 存储（NVR）
- [ ] ⭐ 录像文件组织：按通道 / 日期 / 时间分目录，分段策略
- [ ] ⭐ 录像索引：用 SQLite 记录每段录像的时间范围，快速定位
- [ ] ⭐ 硬盘管理：挂载、剩余空间检测、**循环覆盖最早的录像**
- [ ] 断电保护、文件修复
- [ ] 回放：按时间拖动、倍速、I 帧检索

### 4.9 客户端
- [ ] ⭐ Android MediaCodec（已经会了 ✅，可以作为基础继续深入）
- [ ] ExoPlayer 定制（直播低延迟配置）
- [ ] 自己写播放器：解封装 → 解码 → 音视频同步 → 渲染
- [ ] WebRTC Android SDK
- [ ] Web 端播放：flv.js、hls.js、WebRTC

### 4.10 系统和工程能力
- [ ] 嵌入式 Linux：设备树、驱动基础、Buildroot 定制
- [ ] 多线程和同步：生产者-消费者队列、无锁环形缓冲区
- [ ] 内存和性能：Valgrind、perf、长时间运行的内存泄漏排查
- [ ] 稳定性：看门狗、异常自动恢复、日志系统
